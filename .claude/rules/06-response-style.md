# 06. 응답 스타일 — 짧게, 증거와 함께

> **쉽게 말하면:** 말도 코드도 필요한 만큼만. AI는 내버려 두면 둘 다 과하게 만든다.

AI는 기본적으로 **더 길게 설명하고 더 많은 코드를 쓰는 쪽**으로 기운다. 읽고 리뷰하는 비용은
전부 사람이 치르므로, 분량을 줄이는 것 자체가 품질 규칙이다.

## 1. 답변

- **질문에 답하는 데 필요한 만큼만** 쓴다. 할 일이 하나면 한두 문장으로 끝낸다.
- 다음은 쓰지 않는다:
  - 작업 전 예고("이제 ~하겠습니다")와 작업 후 반복 요약 — 둘 중 하나만.
  - 방금 보여 준 코드의 재인용·줄별 해설. 바뀐 지점만 `file:line`으로 가리킨다.
  - 요청하지 않은 비교표·장단점 나열. 선택이 필요하면 **추천 하나**와 이유 한 줄.
  - 칭찬·사과·감탄사.
- 긴 설명이 꼭 필요하면 **결론 먼저**, 근거는 그 뒤에.

## 2. 코드

- 요청 범위의 코드만 쓴다. 범위 밖 "개선"은 `rules/10-guardrails.md` 위반이다.
- **추상화는 필요가 증명된 뒤에** 넣는다 — 레이어·래퍼·옵션 객체·제네릭을 "나중을 위해"
  미리 만들지 않는다. 중복은 세 번째 등장에서 합친다(`rules/20-project-structure.md`).
- 주변 코드보다 **주석을 더 많이 달지 않는다**. 코드가 말하는 걸 다시 쓰지 않고, 왜 그렇게
  했는지만 남긴다.
- 같은 결과라면 **줄 수가 적은 쪽**을 고른다. 린터가 복잡도·길이를 강제한다(`rules/50`).

## 3. 보고

- 검증 결과는 있는 그대로. 실패는 출력과 함께, 스킵은 스킵했다고(`rules/05`).
- "완료"는 **증거와 함께**만 쓴다 — 어떤 명령을 돌려 무엇이 통과했는지. 검증 훅이 이를
  기계로 강제한다(`rules/50`의 Stop 훅).
- 모호하면 길게 추측하지 말고 **한 줄로 묻는다**. 다만 명백한 기본값이 있으면 묻지 말고
  진행하고 무엇을 했는지 밝힌다(`rules/15`).

## 4. 언어

- 한국어로 답한다. 코드·식별자·명령어·로그는 원문 그대로 둔다.
- 파일·코드 위치는 `file:line`으로 가리켜 리뷰어가 바로 열 수 있게 한다.
