# 0001. 아키텍처 결정 기록하기

- 상태: accepted
- 날짜: 2026-06-12
- 결정자: 프론트엔드 팀

## 배경 (Context)

이 프로젝트는 여러 횡단적 기술 선택(아키텍처, 상태 관리, 툴링)을 합니다. 기록이 없으면 각
선택의 *이유*가 사라지고 같은 논쟁을 반복하게 됩니다.

## 결정 (Decision)

가벼운 Architecture Decision Record(ADR)를 `docs/adr/`에, `0000-template.md`를 기반으로
순번(`NNNN-title.md`)을 붙여 관리한다. 결정 하나당 파일 하나. ADR은 확정되면 불변이며 —
결정을 바꾸려면 기존 것을 대체하는 새 ADR을 추가한다.

## 결과 (Consequences)

- 긍정적: 결정을 PR에서 코드와 함께 발견하고 리뷰할 수 있다.
- 부정적: 중요한 결정마다 약간의 작성 부담이 있다.
- 후속 작업: 다음 레코드는 `new-adr` Claude 스킬로 스캐폴딩한다.

## 검토한 대안

- **위키 / Notion** — 코드와 멀어지고 코드와 함께 버전 관리되지 않는다.
- **기록 안 함** — 조직의 기억이 사람 머릿속에만 남는다.
